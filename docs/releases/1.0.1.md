# NeoDSE 1.0.1

## Fixes

Rocky Linux 9 with SELinux enforcing could repeatedly restart all three server
services after installation or upgrade:

- Transport and proxy exited with `disable core dumps: permission denied` and
  an AVC denial for `process:setrlimit`. Their systemd units now set both core
  limits to zero before starting the confined process. The application keeps
  its existing core-limit and `PR_SET_DUMPABLE` protections.
- The controller exited with `unlock socket: ... bind: permission denied` and
  an AVC denial for writing a `var_run_t` directory. The packaged SELinux file
  contexts now use `/var/run/neodse-server(/.*)?`, matching Enterprise Linux's
  `/run` substitution. Systemd can label the runtime directory with
  `neodse_server_runtime_t` when it creates it.

The fixes retain SELinux enforcing and the existing service permissions.

Scheduled CEC power-on is now delivered at its configured time even when the
five-minute power-off reminder is active. Closely spaced power-on and power-off
times now execute as configured, with reminder banners and occurrence
deduplication retained.

Swagger now uses `Display operator` as the example service-account name for
both creation and replacement requests.

## Security fixes

Hardened UI IPC socket replacement against time-of-check/time-of-use filesystem
races. The listener now verifies that `/run/neodse` is owned by the UI account,
is not a symbolic link, and is not writable by the group or other users before
examining socket entries. Socket inspection, permission changes and cleanup use
file descriptors anchored to that directory. Stale-socket recovery is retained;
regular files, directories and symbolic links at the socket path are refused.
Shutdown also uses the socket name captured at startup, so a later change to
`NEODSE_UI_SOCKET` cannot redirect cleanup.

## Logging changes

The controller's `API audit` records now require `server.log_level: verbose`
or `debug`, or the corresponding `--verbose` / `--debug` command-line flag.
They are no longer emitted at the default `info` level. This includes mutation
outcomes, denied requests and authentication failures. Redaction and per-source
rate limiting of unauthenticated requests are retained.

The agent now reports HDMI-CEC command results, adapter details, audio-target
selection and fallback, and observed power-state changes at `verbose` and
`debug`. Debug mode adds transmitted and returned frames, reply opcodes, kernel
TX/RX status masks, retry/error counters and exchange durations. Unchanged
successful power probes appear only in debug mode. Command failures retain
their existing INFO-level error entry. A `result=sent` summary describes a
successful exchange; reported power observations identify the display state.

## Breaking changes

- The service-account role `alert_io_operator` is renamed to `alert_operator`.
  API clients must use the new name; the old name is rejected.
- Banner actions, including broadcasts, now require `alert_operator` instead
  of `content_manager`. The alert role covers banners, notification sounds and
  serial actions. Update service-account roles accordingly.
- The controller database schema uses the new role name directly. Existing
  databases are not migrated; a database initialized with the new schema is
  required. No backward compatibility is provided for the previous role schema.

## Upgrade from 1.0.0

Follow the [upgrade procedure](../OPERATIONS.md#upgrades), including backup and
package verification. Update all components to 1.0.1. The server package loads
the corrected SELinux policy, reloads systemd and restarts configured services.
The controller restarts locked; run `sudo neodse-server unlock` to resume it.
The configuration format is unchanged. The API role and database schema changes
above are breaking and require a database initialized with the new schema.

The `core.conf` drop-ins and the local SELinux file-context association used
as a workaround are redundant with this release. After installing the fixed
package, remove only those workaround entries if you added them, reload systemd
and restart the services to validate the packaged configuration alone. Preserve
unrelated local overrides and SELinux customizations.

## Installed-host verification

On EL9 and EL10, test a fresh install and an upgrade from 1.0.0 with SELinux
enforcing and without the workaround entries:

```bash
getenforce
systemctl show -p LimitCORE -p LimitCORESoft neodse-server neodse-transport neodse-proxy
matchpathcon -n /run/neodse-server
sudo ls -ldZ /run/neodse-server
sudo journalctl -u neodse-server -u neodse-transport -u neodse-proxy --since "5 minutes ago"
sudo ausearch -m AVC,USER_AVC,SELINUX_ERR,USER_SELINUX_ERR -ts recent -i
```

Expect both core limits to be zero for all three services and the expected and
actual runtime-directory type to be `neodse_server_runtime_t`. Unlock the
controller and check service readiness. Repeat after restarting the services
and after reboot to verify the recreated directory's context. Review new AVCs;
pre-upgrade denials remain in the audit log.

On a client with a compatible CEC display, enable `agent.log_level: verbose`,
restart `neodse-agent`, and exercise wake-up, standby, mute and volume controls.
Check command outcomes, audio-target selection and the next power observation
with `journalctl -u neodse-agent`. At `debug`, verify frame and kernel-status
diagnostics; at `info`, verify failures remain visible without successful
command summaries. Include a missing or disconnected adapter and an audio
system that requires fallback to the TV when available.

Complete the remaining [release checks](../RELEASE.md) on the exact release
commit before publication. The reported Rocky Linux 9 workaround success does
not replace installed-host verification of the rebuilt RPMs.
